1. ОБЗОР ПРОЕКТА
================================================================================

Проект «Искра» состоит из двух частей:
- Интерпретатор языка программирования на C++ (main.cpp, iskra-runtime.exe)
- WPF-редактор (IskraStudio) на C# (.NET 8.0)

Язык «Искра» имеет русский синтаксис и поддерживает команды:
- Задать/Присвоить — создание/присваивание переменной
- Изменить — прибавление числа к переменной
- Печать — вывод значения переменной

Редактор позволяет создавать проекты, сцены, объекты, управлять ресурсами
(изображения, звуки, скрипты) и экспортировать/импортировать проекты в
формате .iskp (ZIP-архив).

2. ИНТЕРПРЕТАТОР C++ (main.cpp)
================================================================================

2.1. Функция lower_keyword
---------------------------
ПРОБЛЕМА: Функция использует std::tolower для ASCII и жёстко зашитую таблицу
для кириллицы. Это работает, но хрупко:
- std::tolower для не-ASCII символов зависит от локали
- При смешанном регистре (например "ЗаДаТь") обработка корректна
- Но если пользователь введёт латинские буквы в имени команды, они будут
  приведены к нижнему регистру корректно

СТАТУС: By design, но требует доработки для полной надёжности.

2.2. Парсинг чисел (parse_integer)
-----------------------------------
ПРОБЛЕМА: Используется std::from_chars для long long. Если число слишком
большое, from_chars вернёт result_out_of_range, и функция вернёт false.

СТАТУС: Корректно обрабатывается.

2.3. Переполнение при сложении
------------------------------
ПРОБЛЕМА: В команде "изменить" есть проверка на переполнение:
  if ((amount > 0 && current > max - amount) ||
      (amount < 0 && current < min - amount))

СТАТУС: Корректная проверка.

2.4. Обработка BOM
-------------------
ПРОБЛЕМА: BOM удаляется только из первой строки. Если файл пустой или
содержит только BOM, getline вернёт пустую строку, и run_line вернёт true.

СТАТУС: Нормальное поведение.

2.5. Пустое имя переменной
--------------------------
ПРОБЛЕМА: Нет проверки, что имя переменной не пустое. Но input >> name не
считает пустое имя, так как operator>> пропускает пробелы.

СТАТУС: Корректно.

2.6. Имя переменной может быть числом
-------------------------------------
ПРОБЛЕМА: Если пользователь введёт "задать 123 = 5", переменная будет
названа "123".

СТАТУС: Может быть by design, но странно.

2.7. Обработка ошибок при выводе
---------------------------------
ПРОБЛЕМА: std::cout << found->second может упасть, если поток вывода в
ошибке.

СТАТУС: Маловероятно, но возможно.

3. WPF-РЕДАКТОР (IskraStudio)
================================================================================

3.1. ProjectStore.TryUpdate — ПОТЕРЯ ДАННЫХ
--------------------------------------------
ПРОБЛЕМА: При переименовании проекта:
1. Создаётся updatedProject с новым именем
2. Если имя изменилось, папка перемещается через Directory.Move
3. Вызывается Save(updatedProject)

Если nameChanged только в регистре (например, "Проект" -> "проект"), то
Directory.Move не вызывается, но Save попытается сохранить в новую папку,
которой может не существовать на файловой системе без учёта регистра.

СТАТУС: РЕАЛЬНЫЙ БАГ. Может привести к потере данных.

3.2. ProjectContentStore.TryRenameScene — ПОТЕРЯ ДАННЫХ
--------------------------------------------------------
ПРОБЛЕМА: При переименовании сцены:
1. scene.Name = name — имя изменяется в памяти
2. RewriteResourceReferences обновляет code.txt
3. projectStore.SaveProject(project) сохраняет изменения

Если SaveProject упадёт, scene.Name восстанавливается, но
RewriteResourceReferences уже изменил code.txt! Откат вызывает
RewriteResourceReferences с обратными параметрами, но если и это упадёт,
данные будут повреждены.

СТАТУС: РЕАЛЬНЫЙ БАГ. Может привести к повреждению code.txt.

3.3. ProjectContentStore.TryDeleteScenes — ПОТЕРЯ ДАННЫХ
---------------------------------------------------------
ПРОБЛЕМА: При удалении сцен:
1. Файлы перемещаются в staging-папку
2. project.Scenes.RemoveAll(...) удаляет сцены из памяти
3. projectStore.SaveProject(project) сохраняет изменения

Если SaveProject упадёт, сцены восстанавливаются, и файлы возвращаются через
RestoreMoves. Но RestoreMoves восстанавливает только директории, а не
отдельные файлы. Если в процессе перемещения произошла ошибка на середине,
некоторые файлы могут быть потеряны.

СТАТУС: РЕАЛЬНЫЙ БАГ. Может привести к потере файлов.

3.4. ProjectArchiveService.Import — МУСОР
-------------------------------------------
ПРОБЛЕМА: При импорте проекта:
1. Создаётся временная папка .import-{Guid}
2. Файлы распаковываются
3. Directory.Move(temporaryPath, finalPath) перемещает папку

Если Directory.Move упадёт, временная папка удаляется в catch. Но если
процесс убить во время импорта, временная папка останется.

СТАТУС: РЕАЛЬНЫЙ БАГ. Может привести к появлению мусорных папок.

3.5. ProjectArchiveService.Export — ВРЕМЕННЫЙ ФАЙЛ
---------------------------------------------------
ПРОБЛЕМА: При экспорте:
1. Создаётся временный файл destination.{Guid}.tmp
2. Архив записывается
3. File.Move(temporaryDestination, destination, overwrite: true)

Если File.Move упадёт, временный файл удаляется в finally. Но если процесс
убить, временный файл останется.

СТАТУС: РЕАЛЬНЫЙ БАГ. Может привести к появлению мусорных файлов.

3.6. MainWindow.ProjectDialogSave_Click — РАССИНХРОН
-------------------------------------------------------
ПРОБЛЕМА: При сохранении проекта:
1. Вызывается projectStore.TryUpdate
2. Если успешно, projects[projectIndex] = updatedProject! обновляет список
3. Если activeProject совпадает с currentProject, обновляется activeProject

Если projectIndex равен -1 (проект не найден в списке), но TryUpdate успешен,
проект обновится на диске, но не в списке.

СТАТУС: РЕАЛЬНЫЙ БАГ. Может привести к рассинхрону данных.

3.7. MainWindow.ConfirmDeleteEntry_Click — ПОКАЗ УДАЛЁННОЙ СЦЕНЫ
------------------------------------------------------------------
ПРОБЛЕМА: При удалении сцены/объекта:
1. Вызывается projectContentStore.TryDeleteScenes или TryDeleteObject
2. Если успешно, DeleteEntryOverlay.Visibility = Visibility.Collapsed
3. Если showingObjects и сцена ещё существует, вызывается BuildObjectList()

Если сцена была удалена, но activeProject.Scenes.Any(scene => scene.Id ==
activeScene.Id) возвращает true (из-за бага в TryDeleteScenes), то
BuildObjectList() попытается показать удалённую сцену.

СТАТУС: РЕАЛЬНЫЙ БАГ. Может привести к показу несуществующих данных.

3.8. ProjectContentStore.TryCreateScene — МУСОР
-------------------------------------------------
ПРОБЛЕМА: При создании сцены:
1. project.Scenes.Add(created) добавляет сцену в память
2. CreateSceneDirectories(project, created) создаёт папки
3. projectStore.SaveProject(project) сохраняет изменения

Если SaveProject упадёт, сцена удаляется из памяти, и папки удаляются через
DeleteSceneDirectories. Но если DeleteSceneDirectories упадёт, папки
останутся на диске.

СТАТУС: РЕАЛЬНЫЙ БАГ. Может привести к появлению мусорных папок.

3.9. ProjectContentStore.TryCreateObject — МУСОР
--------------------------------------------------
ПРОБЛЕМА: Аналогично созданию сцены, но для объектов.

СТАТУС: РЕАЛЬНЫЙ БАГ. Может привести к появлению мусорных файлов.

3.10. ProjectContentStore.TryRenameObject — НЕ ОБНОВЛЯЕТ code.txt
------------------------------------------------------------------
ПРОБЛЕМА: При переименовании объекта:
1. item.Name = name изменяет имя в памяти
2. projectStore.SaveProject(project) сохраняет изменения

В отличие от переименования сцены, здесь нет вызова
RewriteResourceReferences. Это может быть by design (если объекты не
упоминаются в code.txt), но может быть и багом.

СТАТУС: ВОЗМОЖНЫЙ БАГ. Требует уточнения.

3.11. ProjectArchiveService.ReadProjectName — ПАДЕНИЕ
------------------------------------------------------
ПРОБЛЕМА: При чтении имени проекта из архива:
1. Открывается архив
2. Читается манифест
3. Читаются метаданные проекта

Если архив повреждён, может упасть JsonSerializer.Deserialize. Это
обрабатывается в catch в ImportProject_Click, но не в ReadProjectName.

СТАТУС: РЕАЛЬНЫЙ БАГ. Может привести к падению приложения.

3.12. MainWindow.ImportProject_Click — МУСОР
----------------------------------------------
ПРОБЛЕМА: При импорте проекта:
1. Вызывается archiveService.Import(dialog.FileName, name)
2. Если успешно, projects.Add(imported) добавляет проект в список

Если Import упадёт, временная папка удаляется в catch внутри Import. Но
если процесс убить, временная папка останется.

СТАТУС: РЕАЛЬНЫЙ БАГ. Может привести к появлению мусорных папок.

3.13. ProjectStore.LoadAll — ПРОПУСК ПРОЕКТОВ
-----------------------------------------------
ПРОБЛЕМА: При загрузке проектов:
1. Перебираются все папки в projectsDirectory
2. Для каждой папки читается project.iskra.json
3. Если файл не существует или не может быть прочитан, проект добавляется
   в skipped

Если папка проекта содержит только project.iskra.json, но не содержит
нужных подпапок (sounds, sprites, scripts), EnsureProjectFiles создаст их.
Но если EnsureProjectFiles упадёт, проект будет добавлен в skipped.

СТАТУС: РЕАЛЬНЫЙ БАГ. Может привести к пропуску проектов.

3.14. ProjectStore.EnsureProjectFiles — ПАДЕНИЕ
------------------------------------------------
ПРОБЛЕМА: При создании файлов проекта:
1. Создаются папки sounds, sprites, scripts
2. Создаётся файл code.txt
3. Для каждой сцены создаются папки sounds/{sceneId} и sprites/{sceneId}

Если сцена имеет недопустимое имя, выбрасывается InvalidDataException. Это
обрабатывается в LoadAll, но не в TryCreate.

СТАТУС: РЕАЛЬНЫЙ БАГ. Может привести к падению при создании проекта.

3.15. MainWindow.ShowCreateProject_Click — НЕПРАВИЛЬНОЕ СОЗДАНИЕ
----------------------------------------------------------------
ПРОБЛЕМА: При нажатии на кнопку создания:
1. Если WorkspaceView видим и activeProject не null:
   - Если showingObjects, вызывается ShowCreateObjectDialog
   - Иначе вызывается ShowCreateSceneDialog
2. Иначе вызывается ShowProjectDialog(ProjectDialogMode.Create, null)

Если пользователь находится в режиме просмотра объекта (showingDetail),
кнопка создания может создать объект в неправильной сцене.

СТАТУС: РЕАЛЬНЫЙ БАГ. Может привести к созданию объекта в неправильной сцене.

3.16. MainWindow.OpenProject — НЕОБНОВЛЕНИЕ LastOpenedAt
---------------------------------------------------------
ПРОБЛЕМА: При открытии проекта:
1. Вызывается projectStore.MarkOpened(project)
2. Если упадёт IOException или UnauthorizedAccessException, показывается
   MessageBox

Если MarkOpened упадёт, проект всё равно откроется, но LastOpenedAt не
обновится. Это может привести к тому, что "Недавний проект" будет показывать
неправильный проект.

СТАТУС: РЕАЛЬНЫЙ БАГ. Может привести к неправильному отображению недавнего
проекта.

3.17. MainWindow.ExportProject_Click — ВРЕМЕННЫЙ ФАЙЛ
------------------------------------------------------
ПРОБЛЕМА: При экспорте проекта:
1. Вызывается archiveService.Export(project, dialog.FileName)
2. Если успешно, показывается MessageBox

Если Export упадёт, временный файл удаляется в finally внутри Export. Но
если процесс убить, временный файл останется.

СТАТУС: РЕАЛЬНЫЙ БАГ. Может привести к появлению мусорных файлов.
